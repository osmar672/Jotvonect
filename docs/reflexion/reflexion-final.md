# Reflexión final
NotebookLM puede apoyar la planificación mediante preguntas sobre arquitectura, HTTP, autenticación y procesos de empleabilidad. Durante el desarrollo, sus respuestas deben contrastarse con el contrato del proyecto y probarse en el navegador.

Las consultas pueden cambiar decisiones cuando muestran una alternativa más clara, pero la decisión final corresponde al equipo. La validación humana es necesaria para detectar errores, límites de DummyJSON y problemas de UX.

Aprendizajes: separar responsabilidades reduce acoplamiento; un contrato estable facilita integrar ramas; PUT y PATCH tienen propósitos distintos; el estado local es necesario cuando la API simula mutaciones.

Resultado esperado: una aplicación modular, documentada y comprobable.
